# Импорт карт для Virtual TTG

Внешний модуль [Virtual TTG](https://github.com/TTG-Club/vttg): переносит карту
из редактора прямо в сцену мира — вместе со стенами, дверями и светом.

Работает с форматом **Universal VTT** (`.dd2vtt`, `.uvtt`, `.json`). Его
экспортирует **Dungeondraft** (File → Export → Universal VTT), а также Dungeon
Alchemist, Arkenforge и другие редакторы — поэтому парсер один на всех.

## Что импортируется

| Из файла карты | Во что превращается | Примечание |
|---|---|---|
| `image` (base64) | фон сцены | сервер перекодирует в WebP; размеры сцены берутся по РЕАЛЬНО загруженной картинке |
| `resolution.pixels_per_grid` | размер клетки (`custom`) | масштаб пересчитывается, если сервер сжал фон |
| `line_of_sight` | стены | блокируют движение, зрение и свет |
| `objects_line_of_sight` | стены | мебель и колонны; отключаемо |
| `portals` | двери / скрытые двери / окна | вид выбирается в мастере; `closed` переносится в состояние двери |
| `lights` | источники света | `range` (клетки) → радиусы в пикселях, `intensity` приводится к 0–1 |
| `environment.baked_lighting` | предупреждение | если свет впечён в картинку, импорт огней выключается |

Сцена создаётся **скрытой** — покажите её игрокам, когда закончите правки.

## Установка

```bash
pnpm install
pnpm build
node scripts/installToWorld.mjs "D:/путь/к/папке/мира"
```

Модуль попадёт в `<папка мира>/modules/map-import/`. Дальше в мире:
настройки → «Управление модулями» → «Перезагрузить мир». В левом тулбаре сцены
у мастера появится кнопка импорта.

## Требования к хосту

Модулю нужны разрешения `scene-write` и `assets` — они появились в API вместе с
этим модулем. Хост должен уметь:

- `api.scene.createScene / addWalls / addLights / openScene`
- `api.assets.upload / resolveUrl`

Полный контракт — в `docs/MODULES.md` репозитория хоста. Сервер независимо
проверяет роль: импорт работает только у мастера.

## Разработка

```bash
pnpm dev            # пересборка при изменениях
pnpm type-check     # проверка типов
pnpm test           # тесты парсера и конвертера
pnpm make:sample    # образец карты fixtures/sample.dd2vtt
```

`pnpm make:sample` рисует настоящий `.dd2vtt`: комната 8×6 клеток со стенами,
дверью, окном, мебелью и двумя огнями. Им удобно проверять импорт, не запуская
Dungeondraft — на нём же держатся тесты парсера.

Сборка — IIFE (`dist/client.js` + `dist/styles.css`): хост грузит модуль обычным
`<script>`, а Vue берётся из `globalThis.Vue` хоста, чтобы компоненты работали на
том же экземпляре Vue, что и приложение.

Структура:

```
src/
├── main.ts              регистрация модуля, кнопка в тулбаре
├── types/vttg.ts        типы хостового API (копия контракта из docs/MODULES.md)
├── uvtt/schema.ts       zod-схема формата
├── uvtt/parse.ts        чтение файла, сводка, распаковка base64-картинки
├── uvtt/convert.ts      геометрия: клетки → пиксели, полилинии → стены
├── import/runImport.ts  сценарий импорта целиком
└── ui/                  мастер импорта и кнопка тулбара
```

## Тонкости формата

- **Координаты** в Universal VTT заданы в КЛЕТКАХ, а не в пикселях. Часть
  редакторов пишет их относительно экспортированного куска, часть — в координатах
  исходной карты; модуль определяет это по выходу точек за границы и при
  необходимости вычитает `map_origin`.
- **Цвет света** — hex-строка Godot (`RRGGBBAA`, альфа В КОНЦЕ), потому что
  Dungeondraft построен на Godot. Берутся первые шесть символов.
- **Сжатие фона.** Сервер мира всегда перекодирует изображения в WebP и ужимает
  стороны больше 8192 px. Поэтому масштаб считается по загруженной картинке, а не
  по данным файла — иначе стены разъезжаются с фоном.
